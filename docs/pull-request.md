## 为什么单独开一个分支

`master` 里带着只对本仓库有意义的元信息（安装包二进制、指向本仓库的地址、关于对话框的署名），直接提会给审阅者制造噪音，所以 `pr/upstream-1.6.4` 里做了这些处理：

- 去掉 `release/` 下的 `.eext` 二进制
- `extension.json` 的 `homepage` / `bugs` 改回上游地址，只保留版本号
- `src/index.ts` 关于对话框恢复原样（`dist/index.js` 同步）
- README 改成面向项目本身的文档，不再写 fork 声明
- 8 个提交压成 1 个，避免「修上一个提交」式的补丁提交混进评审

## PR 描述

````markdown
这个 PR 在现有基础上做了较大改动，核心是把「只有正方形 + 迭代次数」的参数模型换成按实际工艺参数生成，并补上了双面板常用的双面走线。

### 主要改动

- **参数模型**：改为输入线宽、间距、区域宽高。步距 = 线宽 + 间距，横纵一致，格子始终是正方形，矩形区域靠行列铺满而不是把曲线拉长。
- **矩形区域的曲线形状**：长宽比达到 2:1 时先沿长边二分，再在四个出口方向上挑一条最长直线段最短的走法，避免矩形区域退化成梳状长条（63×126 网格最长直线段从 64 降到 4）。
- **双面错开**：底层整体偏移半个步距，正好落在顶层走线的空隙里，正反面交替走线，发热更均匀。
- **过孔串联**：远端打一个过孔把正反面接成一条回路，近端两层各引出一段线作为接线端子（双端都打过孔会短路成环，所以只做单侧过孔）。
- **电阻**：按铜厚与温度计算 R = ρ(T)·L/(w·t)，ρ₂₀ = 0.01724 Ω·mm²/m，α = 0.00393 /℃，铜厚按 oz 输入（1 oz = 35 μm，可自行填写）；顺手把「铜线阻值计算器」的电阻率从 18.51 改成 17.24。
- **面板**：实时显示步距、网格、实际尺寸、铜箔线长与电阻，并在间距/步距不合理时给出提示。
- **绘制速度**：先把同向连续线段合并成一条（51×51 网格图元从 5204 降到 3043），再按 24 段一批并发提交，不再逐段 await。
- **模式语义**：0/1/2/3 直接标注为起点所在角（左下/右下/左上/右上），四张示例图按新逻辑重画。
- **清理**：移除 `.idea/`，README 补充功能清单与截图（截图放 `docs/` 且不进扩展包）。

### 验证方式

- 几何：对 1..20 × 1..20 全部组合 × 4 个起点模式做了穷举校验（覆盖全部格子、相邻格只差一格、不重复访问）。
- 端到端：用 Node `vm` 打桩 `eda` API，跑完整绘制流程，检查图元数量、层号、过孔位置与端子。
- 界面：380×740 面板逐项检查无裁切。

### 需要注意

- 双面串联依赖 `eda.pcb_PrimitiveVia`，这个 API 在 2.2.35 上还是 beta，代码里做了存在性判断，缺失时会提示而不是静默失败。
- `pcb_PrimitiveLine.create` 的线宽参数目前按 mil 传入并附带注释（注释里提到 2.2.35.4 已修复），在更新的 EDA 版本上可能需要复核。
- 版本号沿用了自己迭代下来的 1.6.4，如果想改成 1.4.0 之类更贴合现有序列，可以调整。
- 顺带一提，实时显示的步距/网格信息大概也能覆盖 issue #3 里想要的线距计算。

改动较大，如果需要拆成多个提交或者调整其中某块的实现方式，告诉我即可。
````

## 之后的维护

- 上游有新提交时，把预整理分支挪到最新上游上再推：

  ```bash
  git fetch upstream
  git rebase upstream/master pr/upstream-1.6.4
  git push -f origin pr/upstream-1.6.4
  ```

  PR 会自动刷新。这个分支是专门为上游准备的，强推没有副作用。

- 标签不会随 PR 合并：`v1.6.x` 这些 tag 只在本仓库，合并后由上游决定版本号与发版节奏。
- 如果上游长期没有回应：先在本仓库继续维护，必要时在 PR 里留言，或在相关 issue 下面说明需求已被覆盖。
